# ADR-0521 — Spring AI 2.0.x on Boot 4.1.x

**Status:** ACCEPTED
**Date:** 2026-06-13
**Reversal cost:** LOW
**Supersedes:** ADR-0517
**Inherits from:** ADR-0520 (Boot 4.1.x baseline)
**Owner:** Principal Engineering

---

## Context

ADR-0517 adopted Spring AI 1.1.x on Boot 3.x. ADR-0520 superseded the Boot 3.x baseline with Boot 4.1.x. Spring AI 2.0 requires Boot 4 as a hard dependency; Spring AI 1.1.x targets Boot 3.x only. With Boot 4.1.x as the mandatory platform, Spring AI 2.0.x is the correct and only viable Spring AI version.

---

## Decision

ChaosForge adopts **Spring AI 2.0.x** (GA as of ~May 28, 2026; 2.0.0-RC1 released June 6, 2026). Pin `spring-ai-bom:2.0.0`. No SNAPSHOT. Ollama local default is unchanged — the model provider decision from ADR-0517 is valid and carried forward.

---

## Spring AI 2.0 API Changes Relevant to ChaosForge

| Change | Phase A impact | Phase B impact |
|---|---|---|
| `PromptChatMemoryAdvisor` deprecated; new APIs require explicit conversation IDs | None — Phase A uses stateless authoring calls | Note for any chat-memory features |
| Setter methods removed from `ChatOptions` — builder pattern only | Use `OllamaChatOptions.builder()` throughout | Same |
| `spring-ai-advisors-vector-store` renamed to `spring-ai-vector-store-advisor` | None | Import rename for RAG wiring |
| `BeanOutputConverter` + `.entity(Class)` stable across 1.x → 2.0 | **No change** — structured-output path unaffected | Same |
| MCP SDK upgraded to 2.0.0-RC1 | No impact — ChaosForge doesn't use MCP | Same |

---

## Alternatives

**Spring AI 1.1.x on Boot 4:** Not supported. Spring AI 1.1.x has a hard Boot 3.x dependency; it will not resolve on a Boot 4 platform. Not a viable option. Rejected.

**No Spring AI (implement LLM client manually):** `RestClient` call to Ollama's OpenAI-compatible endpoint. Valid but loses structured output, advisor framework, and BOM-managed dependency alignment. More implementation work for no portfolio signal gain. Rejected.

---

## Consequences

**Positive:**
- BOM-managed dependency graph aligned with Boot 4.1.x. No version conflict.
- Spring AI 2.0's structured output (`BeanOutputConverter`, `.entity(Class)`) is the Phase A showcase — stable and well-supported.
- Phase B RAG via pgvector is a supported Spring AI 2.0 vector store.

**Negative:**
- Spring AI 2.0 is newer than 1.1.x — fewer community examples as of June 2026. API surface more likely to have rough edges. Mitigated by pinning to GA (not RC1) and limiting scope to Phase A (structured output, no chat memory, no vector store yet).

---

## Failure Modes

| Failure | Detection | Mitigation |
|---|---|---|
| `OllamaChatOptions` built with deprecated setters (from 1.x examples) | Compilation warning → error on Boot 4 / Spring AI 2.0 | Use `builder()` pattern exclusively; `AI integration guidelines` documents this |
| `BeanOutputConverter` produces invalid JSON (model doesn't follow schema) | `IllegalArgumentException` in converter; surfaces as 500 | Resilience4j CB on Ollama client; system prompt instructs JSON-only output |

---

## Implementation Notes

- Gradle: `spring-ai-bom:2.0.0` via `platform(...)` in `control-plane/build.gradle.kts`; `spring-ai-starter-model-ollama` in `control-plane` module only.
- Zero Spring AI dependencies in `edge-gateway` or `execution-service` modules.
