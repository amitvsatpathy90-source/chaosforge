# ADR-0512 — Lab Benchmarks Disclose Full Rig

**Status:** ACCEPTED
**Date:** 2026-05-20
**Reversal cost:** LOW
**Owner:** Principal Engineering

---

## Context

ChaosForge will publish throughput and latency figures in the README and a dedicated benchmark record. Without full rig disclosure, these figures are unverifiable and misleading to reviewers. A portfolio artifact that makes production-equivalent performance claims without context is worse than no benchmarks at all.

---

## Decision

Every published benchmark must disclose:

1. CPU model + core count
2. RAM (total and JVM heap `-Xmx`)
3. JVM version + GC algorithm + relevant JVM flags
4. Kafka (Redpanda) config: RF, partition count, `acks` mode
5. Postgres version
6. Warmup protocol (duration, request count before measurement window)
7. Measurement window (duration, request count)
8. Concurrency level (threads / VTs / connections)
9. Virtual threads enabled (yes/no)
10. Resilience4j active (yes/no; which instances)

A benchmark missing any of these ten fields is **removed** and re-run.

No production extrapolation. Every benchmark is labelled "Lab benchmark — [hardware] — not a production claim."

---

## Consequences

**Positive:** Reviewers can reproduce benchmarks. Figures are credible precisely because they are scoped.

**Negative:** Benchmarking is more work. Acceptable — the credibility cost of non-disclosed benchmarks is higher than the effort cost of disclosure.

---

## Implementation Notes

- README links to the benchmark record; does not embed figures inline (avoids stale README numbers).
