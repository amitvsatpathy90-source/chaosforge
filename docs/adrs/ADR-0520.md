# ADR-0520 — Spring Boot 4.1.x as ChaosForge Platform Baseline

**Status:** ACCEPTED
**Date:** 2026-06-13
**Reversal cost:** HIGH
**Owner:** Principal Engineering

---

## Context

Spring Boot 3.3.x (the prior implicit ChaosForge baseline) reached OSS EOL in June 2025. Spring Boot 3.5.x (the last 3.x branch) OSS support expires June 30, 2026 — days from this decision. Spring Boot 4.0.x went GA on November 20, 2025; 4.1.x is current stable as of June 2026, built on Spring Framework 7.0 and Spring Security 7.0. Operating on an EOL 3.x platform means no security patches from June 30, 2026 — a real compliance risk, not theoretical.

Additionally, key Spring ecosystem projects now require Boot 4: Spring AI 2.0, Spring Modulith 2.0. Remaining on Boot 3.x creates a coupled migration debt that grows with time.

---

## Decision

**All ChaosForge services target Spring Boot 4.1.x.** This is a platform migration, not a version bump. The migration path is: 3.3.x → 3.5.x (fix all deprecations) → 4.0.x → 4.1.x. No direct jump from 3.x to 4.0 without the intermediate 3.5 step.

---

## Alternatives

**Remain on Boot 3.5.x until Boot 4.2:** Defers the migration but runs unpatched from June 30, 2026. For a portfolio artifact, no live users are at risk; but a reviewer seeing "EOL platform" is a credibility hit, not a credibility signal. Rejected.

**Migrate to Boot 4.0.x (not 4.1.x):** Boot 4.0.x support ends 2026-12-31. Migrating to 4.1.x now extends the support window to ~June 2027. No additional migration cost to go directly to 4.1.x. Rejected.

---

## Consequences

**Positive:**
- Platform is patched and current.
- Spring AI 2.0 and Spring Modulith 2.0 become available (ADR-0521).
- Native image (GraalVM) performance improves significantly due to modular autoconfigure.
- Built-in API versioning for REST endpoints.

**Negative (breaking surfaces ChaosForge must address):**
- **Jackson 2 → Jackson 3:** `JacksonException` now extends `RuntimeException`, not `IOException`. `catch (IOException e)` blocks in outbox payload serialization and REST error handlers will silently miss Jackson errors. Audit all JSON boundaries; run output-shape comparison tests.
- **Spring Security 7:** Filter chain DSL changes. JWT filter wiring and `@PreAuthorize` config need review. Three-layer tenant isolation structure (ADR-0509) is unchanged; DSL to wire it changes.
- **Spring Kafka 4.0:** `@KafkaListener` wiring and `KafkaTemplate` producer config surfaces change. Execution Service consumer wiring needs verification.
- **JSpecify null safety:** `org.springframework.lang.@NonNull/@Nullable` deprecated; migrate to `org.jspecify.annotations.*`. Compile-time hygiene, not a runtime break.
- **Modular autoconfigure:** `spring-boot-autoconfigure` split into 70+ JARs. Audit any direct imports from internal Boot autoconfigure packages.
- **Undertow removed:** ChaosForge uses Netty (Gateway) and Tomcat (CP/Exec). No action needed.
- **Liveness/Readiness probes on by default:** Include intentionally in actuator config.

---

## Failure Modes

| Failure | Detection | Mitigation |
|---|---|---|
| Jackson `catch (IOException e)` missing Jackson 3 errors | Silent error swallowing in outbox serialization path | Audit + integration test asserting Jackson errors surface as 500, not silently dropped |
| Security 7 filter chain misconfiguration post-migration | Cross-tenant access succeeds (should 404) | Integration test: T2 JWT → T1 resource → assert 404 |
| Spring Kafka 4 consumer wiring regression | Kafka consumer doesn't start; `rpe.consumer.lag` rises | Integration test: publish message, assert consumed within 5s |

---

## Validating Assumptions

| Assumption | Type | Invalidator |
|---|---|---|
| Boot 4.1.x is compatible with all ChaosForge dependencies | ASSUMED | Dependency resolution at `./gradlew build`; any unresolved transitive = investigate |
| Jackson 3 JSON output shape matches Boot 3.x for all existing REST endpoints | ASSUMED | Comparison test suite required before promoting |

---

## Implementation Notes

- Migration tooling: OpenRewrite Boot 3→4 recipes for mechanical renames. Manual validation of JSON shapes and Security filter chains always required regardless of tooling.
- `spring-boot-starter-classic`: transitional bridge for Jackson 2 compatibility during migration. Use transiently; remove before Week-10 hard cut.
