# ADR-0537 — Every Silent-Failure Mode of a Resilience Mechanism Must Be Observable

| **Reversal cost** | LOW (alert rules + two counters; no runtime behaviour change) |
| **Deciders** | Principal Engineering |

## Context

An architecture audit (arch-audit H3) found that several mechanisms whose whole job is to make failures
**loud** were themselves failing **silently** — the metric existed but no alert consumed it, or the alert
was scoped so it could not see the failure, or the code path emitted no signal at all. The rules and SLI
tables already *claimed* these were covered; the alert file did not match. (Doc-vs-code drift on the
observability surface is itself the hazard: an operator trusts a runbook that points at an alert that
never fires.)

Concretely, on the running lab Prometheus (whose entire alert surface is `docker/prometheus/alerts.yml` —
one `rule_files` entry, no Grafana-managed alerting):

- **The `_default`-partition trap had no alert.** `partitioning-rules.md §1` mandates alerting on
  `chaosforge.partition.default_rows > 0` — the one C28 failure that cannot self-heal (a row in an
  un-droppable default partition permanently blocks that day's real partition). The gauge was registered;
  no rule watched it.
- **The straggler backlog had no alert.** The SLI table lists `outbox.pending_outside_claim_window`
  ("alert > 0 sustained") — the signal that rows are aging toward their partition-drop age before
  delivery. No rule existed.
- **The outbox alerts were scoped `job="control-plane"` only**, so the exec **result-event** relay
  (`job="execution-service"`) — an equal outbox with the same DEAD/lag failure modes — was unmonitored.
- **The command-accept P99 alert aggregated the AI authoring path.** Local Ollama inference is
  intentionally 10–60s (architecture specification); folding `/v1/ai/**` into the P99 made the 300ms command-accept SLO
  fire permanently and meaninglessly.
- **The gateway rate-limit fail-open was uninstrumented and unlogged.** A Redis blip disables rate
  limiting globally by design — but with no counter and no log, "rate limiting is off" was invisible.
  (The policy-feed silent default is the ADR-0536 half of the same theme.)

## Decision

Adopt the principle: **a resilience mechanism is not complete until its failure is observable and
alertable.** Applied here:

1. **Partition-trap tripwire.** `PartitionDefaultRowsPresent` — `chaosforge_partition_default_rows > 0`
   on both partitioned services (CP outbox; exec inbox + outbox), `severity: page`. Non-zero is an
   incident, not a warning.
2. **Straggler backlog.** `OutboxStragglerBacklog` — `outbox_pending_outside_claim_window > 0` sustained
   15m, both jobs.
3. **Both relays covered.** `OutboxDeadLetterPresent` / `OutboxRelayLagging` broadened to
   `job=~"control-plane|execution-service"` with `by (job)` + `{{ $labels.job }}` so the alert names which
   relay is stuck.
4. **P99 excludes the LLM path.** `CommandAcceptLatencyP99High` adds `uri!~"/v1/ai/.*"` so the SLO
   measures the command-accept path it is named for.
5. **Gateway silent-failure signals.** `RateLimitWebFilter` increments
   `chaosforge.gateway.rate_limit{outcome}` (allowed / rate_limited / fail_open) and WARNs on fail-open;
   `ControlPlaneClient` increments `chaosforge.gateway.policy_load{outcome}` (ADR-0536). Two alerts make
   them actionable: `RateLimitFailingOpen` and `TenantPolicyFeedDown`.

`tenant_id` is never a label on any of these (cardinality rule, unchanged).

## Alternatives Considered

- **Rely on Grafana-managed alerting instead of Prometheus rules.** The lab provisions no Grafana
  alerting; `alerts.yml` is the single source. Adding a second alerting system would fork the surface.
  Rejected.
- **A single catch-all "something is wrong" alert.** Loses the actionability the runbooks depend on
  (which relay? which partition? rate limit vs policy feed?). Rejected — each failure mode maps to a
  distinct response.
- **Wire Alertmanager routing now.** Out of scope: the lab has no pager. These rules reach FIRING in
  Prometheus/Grafana; routing/grouping/silences remain the documented production add-on (unchanged
  limitation).
- **Leave fail-open silent** (it's "by design"). Fail-open is a deliberate availability choice, but
  *invisible* fail-open means rate limiting can be globally off with no signal. The design choice and its
  observability are independent; keep the behaviour, add the signal. Rejected the status quo.

## Consequences

- Every C28 / relay / rate-limit failure mode named in the rules and SLI tables now has a rule that can
  actually see it; the docs and the alert file agree.
- `alerts.yml` validated (10 rules, each with `expr` + runbook). No runtime behaviour changed — these are
  observation-only additions plus two gateway counters.
- Runbooks reference `docs/runbooks/dlq-and-outbox.md` for the new outbox/partition alerts.
- Residual (unchanged): no Alertmanager in the lab — alerts fire in Prometheus/Grafana, not to a pager.
