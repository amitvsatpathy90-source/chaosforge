# ADR-0506 — x-replay-* Namespaced Outbox Header Extension

**Status:** ACCEPTED
**Date:** 2026-05-20
**Reversal cost:** LOW
**Owner:** Principal Engineering

---

## Context

The canonical outbox pattern defines a `headers` JSONB column on the outbox table for producer-set metadata. ChaosForge's replay engine needs to propagate `replay_version`, `scenario_id`, `rule_set_id`, and `rule_set_version` from the Control Plane to the Execution Service as durable, inspectable metadata — not embedded in the payload.

---

## Decision

ChaosForge extends the canonical `headers` JSONB for `ReplayCommand` outbox rows with four keys namespaced under `x-replay-*`:

```json
{
  "x-replay-version":      "<long>",
  "x-scenario-id":         "<uuid>",
  "x-rule-set-id":         "<uuid>",
  "x-rule-set-version":    "<int>"
}
```

These keys are additive and namespaced — they do not conflict with any canonical key. The canonical pattern does not forbid additional keys; it forbids changing canonical key shapes. This is the **single documented deviation point** from the P1 outbox canonical.

---

## Alternatives

**Embed replay metadata in payload body:** Works but mixes transport metadata with business payload. Makes the Execution Service's fencing check dependent on payload deserialization before the header check — wrong order. Rejected.

**Separate replay_metadata table:** Adds a join on every outbox row relay. Operational complexity for no correctness gain. Rejected.

---

## Consequences

**Positive:** Fencing check reads `x-replay-version` from the Kafka message header without deserializing the payload — correct ordering (ADR-0502 fencing-before-inbox rule).

**Negative:** The four keys are ChaosForge-specific and undocumented in the P1 canonical. Any new service consuming these outbox rows must know the extension. Mitigated by the namespace prefix and this ADR.

---

## Implementation Notes

- Outbox relay maps `headers` JSONB keys to Kafka message headers verbatim.
- `x-replay-version` header is a UTF-8 encoded long string on Kafka (`Long.toString(replayVersion).getBytes(UTF_8)`).
